# RL 首游候选研究笔记

**日期：2026-10-14**

> **说明**：本轮研究已按 02 号票确认的新约束重做；上一轮（Atari Pong / Chrome Dino / ViZDoom）的短名单因不符合"仅网页 + roguelike"约束而作废，见"淘汰项"。
>
> **证据口径**：指有明确来源支持的事实，不代表已在本机复测；指运行兼容性、自动化接口、奖励可读性及训练吞吐等尚未实测事项。不补造性能数据，不将文档能力等同于本机可用性。

## 一、已确认约束与本机状态

- **范围**：第一阶段仅做网页游戏，允许浏览器自动化。
- **类型**：roguelike，优先回合制（天然离散步进，无时序压力）。
- **环境**：无头 Linux + Xvfb，无 GPU，纯 CPU 训练。
- **预算**：墙钟时间为几天量级。
- ****：当前无 Docker，无 Chromium/Firefox，需后续安装。
- **评估原则**：优先可本地运行、可重复重置、输入稳定、奖励可观测的方案。三个候选均尚未验证能否在预算内完成有效训练。

## 二、候选逐项评估

### 1. DCSS 自建 webtiles：优先 Sprint 模式

**定位**：回合制 roguelike，通过浏览器访问 webtiles；优先考察短局 Sprint 模式。

####

- `nkhoit/dcss-webtiles` 提供 Docker 自建方案，包含标准、自定义种子、教程、Sprint 四种模式；本地服务入口为 `http://localhost:8080`。DCSS 使用 GPLv2。
- 来源：https://github.com/nkhoit/dcss-webtiles
- 官方站提供在线游玩入口，可作为另一路径，但不等同于本地可控环境。
- 来源：https://crawl.develz.org/
- morgue 文件记录每局统计，包括分数、等级、深度、死因等，可作为局末奖励解析的候选来源。
- 来源：https://wiki.tilde.institute/w/dcss
- Sprint 是短局模式；"短局"本身不能推出具体交互步数或训练吞吐。

#### 交互与奖励方案

- **画面**：浏览器截图，观察 webtiles 客户端。
- **输入**：键盘，拟使用 vi 键或方向键；具体键位映射和焦点行为需实测。
- **重置**：通过菜单开新局；文档提供自定义种子模式，但 Sprint 与种子设置的组合能力及自动化流程待验证。
- **奖励**：
- 局末：优先解析 morgue 文件（文本，含 score / XL / 深度 / 死因）。
- 局内：拟读取 HUD 中的 XL、深度、金币；字段可见性、OCR 准确度及信号有效性均待验证。

####

- 本机能够安装并运行 Docker，容器内游戏可正常启动。
- Sprint 单局步数适合几天量级预算。
- morgue 文件可被训练进程稳定获取，字段格式足够稳定。
- Xvfb 下键盘输入延迟、动画等待和状态同步可接受。
- 裁剪动作空间后，纯 CPU 截图训练能获得可用吞吐。

#### 主要风险

- 游戏复杂度高，动作空间大，需要后续票明确动作裁剪与菜单处理范围。
- 当前缺少 Docker 和浏览器，部署前置工作最多。
- GPLv2 需纳入依赖与分发合规检查；仅作为依赖或服务使用通常不等同于分发，但仍应按实际集成方式判断。

**阶段判断**：保持第一顺位，但必须先验证"部署—开局—输入—终局—取 morgue—重开"的闭环，不能仅凭功能丰富认定其最适合首训。

### 2. ruggrogue（web）

**定位**：回合制 roguelike，浏览器运行 Emscripten 版本；可考虑本地静态托管。

####

- 提供可直接访问的网页版本。
- 来源：https://tung.github.io/ruggrogue/
- 仓库根目录自带 `index.html` 与 `ruggrogue.js`，支持本地静态自建（无需 Docker）。
- 代码为 MIT 开源，tiles 为 CC0（Urizen 1Bit Tilesets），字体为 WTFPL。
- 键盘操作文档覆盖八向移动、等待、物品热键、下楼梯。
- 机制包含饥饿、装备、怪物及层数递进，相比 DCSS 更简单。
- 来源：https://github.com/tung/ruggrogue

#### 交互与奖励方案

- **画面**：浏览器 canvas 截图。
- **输入**：键盘。
- **重置**：开新局；具体按键、死亡后界面和自动化路径待验证。
- **奖励**：拟使用深度、等级、击杀等信号；HUD 是否显示这些字段、字段含义及读取方法均待确认，暂不视为已具备的奖励接口。

####

- 无头 Chromium + Xvfb 下 canvas 可正确渲染并接收键盘焦点。
- 仓库内网页资产可在本地静态服务下完整运行。
- 单局时长、重置成本及交互吞吐适合预算。
- 可从截图中稳定提取至少一种进度或终局信号。

#### 主要风险

- 项目规模较小（GitHub 显示 82 stars），维护情况需核查。
- 机制较简单，作为通用 roguelike RL 基准的代表性可能有限。
- 奖励读取与自动重置尚未形成已验证方案。

**阶段判断**：保持第二顺位。若 DCSS 复杂度或部署成本不可接受，优先将其作为首游替代；静态自建不要求 Docker，但仍需安装浏览器。

### 3. Desktop Dungeons HTML5 版

**定位**：回合制、偏解谜的地牢游戏；候选为旧 alpha 的第三方 HTML5 转换版。

####

- 官方提供免费 alpha，并在官方页面链接 Laurent Vaucher 的第三方 HTML5 转换版。
- 官方来源：https://www.desktopdungeons.net/media/
- 浏览器入口：http://www.desktopdungeons.net/HTML5（页面可访问，标题为 "A web rendition of the excellent Desktop Dungeons by QCF Design"）
- RPS 曾报道其 HTML5 浏览器版本。
- 来源：https://www.rockpapershotgun.com/the-deeper-dungeons-desktop-dungeons-out-next-week
- VG247 评测摘要称单局约 10–15 分钟（搜索结果摘要，原文未独立打开核验）。

#### 交互与奖励方案

- **画面**：浏览器截图。
- **输入**：拟通过鼠标点击移动、战斗；转换版的实际点击区域与响应需实测。
- **重置**：拟使用重开按钮；位置、流程及状态恢复方式待验证。
- **奖励**：拟读取分数；具体显示位置、结算时机和读取方式待验证。

####

- 该第三方转换版仍可访问，并能在现代无头 Chromium 下正常运行。
- 回合推进、鼠标操作和重开流程可稳定自动化。

#### 主要风险

- 旧版第三方转换的兼容性与可维护性风险最高。
- 官方免费 alpha 不等于转换版具有已确认的开源或再分发许可。
- 在浏览器启动、重置与分数读取通过验证前，不宜投入训练预算。

**阶段判断**：保持第三顺位，仅作备选。

## 三、淘汰项

| 项目 | 淘汰理由 |
|---|---|
| Brogue CE | 当前为桌面 SDL2 路径，无官方 web 版，不符合第一阶段仅网页的范围。 |
| Atari Pong / Chrome Dino / ViZDoom | 上一轮短名单；非网页或非 roguelike，不符合新约束。 |
| 2048 | 虽为网页游戏，但非 roguelike。 |
| NetHack 公共服务器 | 存在公共服务 ToS、自动化许可及网络依赖问题，本阶段不选。 |
| Shattered Pixel Dungeon | 无官方 web 版，不符合当前选型范围。 |

## 四、排序与验证门槛

1. **DCSS 自建 webtiles Sprint**
2. **ruggrogue web**
3. **Desktop Dungeons HTML5**

此排序是研究优先级，不是已测得的性能排名。建议先安装浏览器，再进行最小闭环验收：

- 能稳定截图与发送输入。
- 能辨认开局、运行中、终局状态。
- 能无人值守重置并连续运行多局。
- 至少能稳定取得一个奖励信号。
- 实测单步耗时、单局步数、重置耗时，再判断几天预算是否可行。

## 五、待用户确认

- 是否接受 DCSS 的复杂度，以及后续对动作空间和菜单功能进行裁剪？
- 是否接受 ruggrogue 较简单、代表性较弱，换取较低部署门槛？
- 是否接受 Desktop Dungeons 的第三方转换版及其兼容性、许可不确定性？
- 是否愿意在本机安装 Docker 和浏览器？若不愿安装 Docker，是否优先推进 ruggrogue 本地静态版？
